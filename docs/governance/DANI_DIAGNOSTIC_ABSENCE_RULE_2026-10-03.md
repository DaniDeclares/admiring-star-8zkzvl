# DANI Diagnostic Absence Rule

An empty result, missing UI surface, stale queue, or unavailable historical relation does not by itself establish that a DANI capability is absent.

Before replacement work, inspect current main, older migrations and pull requests, current runtime objects, historical entry paths, reconciliation state, and existing consumers. Determine whether the symptom comes from historical data shape, evolved authority, environment drift, unconsumed intake, or a genuine gap.

Only a demonstrated genuine gap justifies new architecture.
