# DANI Downstream History Checklist

Use before every downstream implementation or release decision.

- [ ] Current canonical main inspected.
- [ ] Relevant merged PRs inspected.
- [ ] Relevant open PRs inspected for overlap.
- [ ] Relevant closed-unmerged/abandoned work inspected.
- [ ] Relevant migrations and tests inspected.
- [ ] Relevant proof/runtime receipts inspected.
- [ ] Tester current truth inspected when applicable.
- [ ] Production current truth inspected when applicable.
- [ ] Bridge/promotion/drift evidence inspected when applicable.
- [ ] Prior lineage classified: CURRENT AUTHORITY / STILL VALID-REUSE / SUPERSEDED / FAILED-ABANDONED / DRIFTED / GENUINELY MISSING.
- [ ] Existing mechanism run or repaired before any replacement is proposed.
- [ ] New architecture justified by a demonstrated gap, not by an empty result or stale view.
- [ ] Exact-head tests/proof passed.
- [ ] Governed promotion path used.
- [ ] Exact Production runtime verified before GREEN is claimed.
